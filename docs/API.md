# Record API

`GET /api/bank/records/{kind}/{id}` and MCP `record_get(kind, id)` return `{kind, record}` with the exact native JSON object. Use an existing server id, including the PWA sync id mapping. Missing ids (including `new`) return 404 and never create objects.

`PATCH /api/bank/records/{kind}/{id}` takes a JSON object containing only changed fields. MCP `record_patch` takes `{kind, id, patch}`. A single transaction reads the latest object, applies the supplied fields, validates study question/concept content, recalculates hashes and writes the revision and search index. Omitted fields retain concurrent edits. `null` removes an optional field; nested objects and arrays replace their entire field. Identity, creation time, update time and content hash are generated by the server and must be omitted. Empty or unchanged patches do not create revisions. A deleted object is never resurrected.

Kinds are the native study tables: subject, topic, question, session, pdfAnchor, keyConcept, exam, deliverable, gradingConfig and installedPackage. Teacher kinds (class, student, teacherExam, rubric, gradingBatch, submission, proposal, teacherSettings) use the same read/patch contract while retaining their separate local-only teacher store and teacher sync revisions; they never enter study backups. Notebook chats retain their existing dedicated tools.

For a form, keep its initial snapshot, compute differences against the draft, and submit those differences. Sending a complete stale object can still overwrite fields by explicitly changing them. Same-field concurrent changes follow the latest submitted patch. The existing question_update tool also reads the latest question inside its write transaction.

## Shared copilot transport

GET `/api/copilot/info` returns app/data-space identity and panel/settings URLs. GET `/api/copilot/panel.js` serves the configured Faustus panel. POST `/api/copilot/proxy` accepts `{path, method, body?, raw_body?, content_type?, headers?}`; binary/multipart bodies use base64 raw_body. Only the shared Faustus chat/session/copilot namespace is forwarded. JSON and multipart context origin always uses this server's app/data-space identity. Streaming responses, upstream status and run ids pass through. No credentials are returned to the browser.

The frontend context resolves the existing native record_get contract using exact ids, including local-to-server deduplication mappings. Teacher records retain their separate store. Visible forms contribute draft fields and their existing object id. On faustus:turn-end, normal study and teacher synchronization refreshes lists; editor component state survives. A changed-field save updates the latest native row and reflects the complete returned object in the UI.

Notebook legacy continuation calls Faustus POST `/api/hoard-copilot/imports` through the relay with stable `source_thread_id=notebook:<id>` and native message ids, text, dates and citation metadata. Repeating the import deduplicates messages. A deleted canonical conversation is reported instead of silently resurrected. Original notebook rows are preserved. Native cited source Q&A and pedagogical Tutor turns remain available in their dedicated UI; general assistant turns use Faustus. Sessions and composer drafts are scoped to the real subject project (or the app-wide context).

Transport provenance: hypatia/hoard_link/copilot.py is byte-identical to HoardLink main fe828e62322e8614c490458df59d298f904198e0 (the approved shared relay), without the experimental generic installer dependency.

Optional recursive patches: MCP `record_patch(..., merge_objects=true)` and HTTP `PATCH ...?merge_objects=true` merge changed object keys recursively; null removes the supplied key. Arrays continue to replace their field. The default remains the reviewed whole-field replacement contract. Teacher header saves use differences against the form baseline and recursive patches, so changing the centre retains an agent's change to the course. Native forms also supply typed draft snapshots through `hypatia:context-request`, including option choices and ids that are represented by buttons rather than inputs.
